# 禅道与智能生成配置重设计

日期：2026-09-07。状态：主要失败路径已修复并单测闭环（CFG-01 假成功拦截与超时、CFG-02 独立解耦保存、CFG-05 严格地址规范/防跨站泄露一键探测；增加禅道 v1 独立适配器与 AI 协议强校验；待真实环境全链路建单与联调验收，尚不能标记为全部验收通过）。

## 1. 当前问题与设计目标

基于现有 SettingsPage、ZentaoClient、RemoteGatewayProviderAdapter 和 BugEditPage 检查：

1. AI 只提供项目自定义网关地址，没有模型、API Key、协议选择。它不是任意模型服务地址都可用的通用 Provider。
2. AI 连接检测吞掉 JSON 解析错误并默认填充协议版本和全部能力，HTTP 200 的 HTML 登录页、空对象或业务失败对象也可能显示成功。`check_capability` 未在现有网关文档中定义。
3. 禅道连接检测吞掉 JSON 解析错误，用“产品 #ID”兜底显示成功，没有证明响应是有效产品。
4. 禅道地址固定拼接 `/api.php/v2`，不区分站点根地址和 API 根地址；误填完整 API 地址会重复拼接。当前客户端主动拒绝非 localhost 的 HTTP，内网 HTTP 部署无法使用。
5. 产品 ID 和影响版本靠手填，缺少项目、执行、模块、指派人等实际提交上下文；读取产品成功并不意味着能创建 Bug 或上传附件。
6. 两套配置共用保存按钮；AI 地址不完整时连禅道设置也无法保存。配置修改后旧的绿色检测结果不失效。
7. 禅道附件失败状态只保存在页面 state。重新打开页面会丢失“仅重试附件”入口；重试又使用当前配置，修改禅道地址后可能将旧 Bug ID 的附件发到另一站点。
8. 创建 Bug 与附件上传缺少全程超时；连接检测在收到响应头后清除计时器，读取卡住的响应体仍可能无限等待。

目标：让用户明确知道“保存了什么、验证到哪一步、为什么失败、下一步怎么处理”，而不是只看到笼统的连接成功。

不恢复测试用例功能、脱敏、环境切换。凭据访问控制与任务授权是集成基础，不是业务数据脱敏。

## 2. 设置页结构与共用状态

拆成三个独立配置区：智能生成、禅道集成、采集设置。每区独立保存、独立检测和错误提示；可保存不完整草稿，但不完整配置不能启用执行。

每张连接卡显示：名称、启用状态、已保存/有未保存修改、凭据是否可用、最近验证时间、验证范围和结果。

检测层级：

| 层级 | 成功意味着 | 不代表 |
| --- | --- | --- |
| 地址/网络 | 请求到达预期接口 | 身份有效 |
| 协议/鉴权 | 返回符合适配器协议、凭据有效 | 有全部业务权限 |
| 资源/能力 | 能读取目标产品或声明指定 AI task | 实际创建/生成一定成功 |
| 实际操作 | 本次指定生成/提交成功 | 所有模型、产品、附件永久可用 |

测试使用当前草稿的不可变快照。任一字段修改即将旧结果标为“配置已变更，需重新检测”。异步结果带 probeId 和 configRevision，过期响应不得覆盖新配置状态。测试按钮不暗中保存配置。

错误分类统一为：CONFIG、AUTH、FORBIDDEN、NOT_FOUND、PROTOCOL、TIMEOUT、RATE_LIMIT、NETWORK、CAPABILITY、UNKNOWN_OUTCOME。显示可执行建议，无法从浏览器错误区分证书/代理/网络时如实说明，不猜测成 CORS。

## 3. 智能生成：两条接入路径明确分开

在用户确认接入偏好前，按同时兼容两种方式设计；实现可以先交付实际需要的一种。用户无需为了个人使用被迫部署自定义网关。

### 3.1 模式与字段

| 模式 | 配置字段 | 行为 |
| --- | --- | --- |
| 关闭 | 无 | 保留人工编辑、取证与导出 |
| 本地规则 | 无；明确标注“不调用大模型” | 保留现有规则算法 |
| 模型 API 直连（新增） | 连接名、协议类型、API 基础地址、API Key、模型名、超时 | 专用适配器转换项目任务与模型请求 |
| 企业任务网关 | 连接名、完整任务接口地址、鉴权方式、协议版本、超时 | 使用本项目 task/context 协议 |

“协议类型”不等于厂商名称；只列已实现并经过验证的适配器，不显示所有厂商都通用。具体模型协议、路径、结构化输出支持在实现所选适配器时依据对应官方文档确认。

直连路径允许手动输入模型名；模型列表读取是可选能力，列表接口不支持时不能判定模型调用不可用。模型/协议选择须与真实请求一致，不能只在 UI 显示。

网关鉴权第一期支持无鉴权与 Bearer 凭据；如业务需要自定义 Header，再按允许名单扩展。网关凭据与网关服务端的模型 Key 是不同凭据，不把“模型 Key 在服务端”误解为“网关不需要鉴权”。

所有任务复用同一个默认连接，先不引入按任务配置多模型的复杂 UI。连接列表可预留 stable connectionId，后续扩展不影响历史记录。

### 3.2 网关协议与检测

保留现有 `version + task + context`，只支持 `generate_bug`、`analyze_issue`、`plan_form_fill`，不包含用例生成。

补全明确的 `check_capability` 契约，例如：

```json
{
  "data": {
    "version": 1,
    "supportedTasks": ["generate_bug", "analyze_issue", "plan_form_fill"]
  }
}
```

以上是本项目拟定协议，不是模型厂商协议。客户端严格校验对象、版本和 task 数组；HTML、空响应、业务失败、错误版本均不通过。不默认补出能力。未知 task 可展示为扩展能力，但不启用对应按钮。

旧网关不支持能力检测时显示“能力检测未支持”，不直接判断整个生成不可用。用户可主动点击“验证实际生成”，用固定小样例确认指定任务；不得默认发送当前业务表单。

直连模式分别提供“检查配置”和“验证生成”；后者会产生一次小额模型调用，执行前明确提示。验证生成需覆盖结构化结果解析，能输出一段文本不代表能生成合法填表计划。

### 3.3 执行约束

- 本地统一校验业务 schema，覆盖字段/动作类型、选项 ID、重复字段、快照匹配和只填空白策略；不能依赖模型自觉遵守。
- 选择远程模型后失败不能静默改用本地规则并继续显示模型成功；可显式提供“改用本地规则”。
- 切换模型或连接不改变运行中请求的配置；现有任务使用启动时快照。
- 网络、响应体读取、解析均处于超时范围内，支持取消。重试次数和原因可见，避免无界调用。

## 4. 禅道：连接与提交默认值分开

### 4.1 连接设置

基础字段：连接名称、站点地址、API 版本/适配器、Token、凭据保存方式。

地址例子可为 `https://host` 或 `https://host/zentao`。统一保留部署子目录并去掉多余末尾斜线；识别用户粘贴的 `/api.php/v1` 或 `/api.php/v2` 后明确展示解析结果，不重复追加。禁止含用户名密码的 URL，查询参数和 fragment 不静默作为站点地址。

展示最终 API 根地址供用户确认。自动识别仅使用只读调用；明确选定 v1/v2 后提交不跨版本试写，避免重复建单。第一期先确定并验收用户真实版本；其他适配器未实现时显示“不支持”，不只替换路径中的版本号。

HTTPS 默认推荐。若用户实际使用内网 HTTP，可为该明确连接提供“允许明文 HTTP”开关和传输风险提示，不自动降级 HTTPS、不绕过证书验证。是否开放该选项由用户部署需求确认。

凭据方式：默认本次浏览器会话；可选择“记住在本机”，并明确是扩展本地存储，不是加密保险箱。重启导致会话凭据消失时显示“需重新输入凭据”，而非仍显示已连接。

### 4.2 分步配置与一键浏览器获取流程

#### 4.2.1 方案 2：基于网页登录态 Cookie 免 Token 模式 (已实现)
针对用户痛点（在禅道个人中心翻找、复制、输入 Token 过于繁琐）：
1. **免 Token 零配置直连**：
   - 插件借助 Chrome 扩展宿主权限（`<all_urls>` 与 `"cookies"`），在与禅道通信时采用 `credentials: 'include'`；
   - 只要用户在当前 Chrome 浏览器中已打开并登录了禅道网页，无需配置任何 API Token 即可直接通过浏览器会话 Cookie（`zentaosid` 等）进行只读检测、拉取产品/版本以及一键建单；
   - 彻底省去了去个人中心翻找和复制 Token 的繁琐操作。
2. **双鉴权模式无缝支持**：
   - 支持 `authMode: 'cookie' | 'token'`，默认推荐 `'cookie'` 优先；
   - 若用户处于免 Token 模式，仅需站点地址即可测试连接和建单，空 Token 不会受阻；
   - 保留传统「API Token」模式作为高级选项切换，满足在当前浏览器未登录禅道等特殊场景。
3. **友好失效引导**：
   - 若 Cookie 过期或未登录（接口返回 HTML 登录页或 401/403），给出明确友好的引导：“当前浏览器未登录禅道或会话已过期，请在网页中登录后重试”，不误导用户。

#### 4.2.2 一键从当前浏览器获取 (已实现)
针对用户实际自建部署（如 `https://zentao.hbisscm.com/`），提供「一键从当前浏览器获取」功能：
1. **标签页会话匹配**：优先根据填写的站点地址域名匹配已打开的禅道标签页；若未填写，自动通过标题与 URL 中的 `zentao` 或 `禅道` 特征匹配活动标签页；
2. **只读探针提取**：通过 `chrome.scripting.executeScript` 注入安全探针：
   - 读取全局配置 `window.config` 中的账号（`account`）、用户真实姓名（`realname`）、当前产品 ID（`currentProduct`）以及 Token 缓存；
   - 提取页面中的产品下拉框 `#product` 与影响版本下拉框 `#openedBuild` 的当前选中国与完整选项列表；
   - 在当前登录页面的同源上下文下尝试发起 `POST /api.php/v2/tokens` 读取当前用户 API Token；
   - 读取会话 Cookie（`zentaosid`）；
3. **回填与自动联动**：自动规范化并回填 Base URL、Token、当前产品 ID；若获取到 Token，立即自动通过只读 API 拉取该账号有权限的产品列表与该产品的构建版本列表供下拉选择；
4. **友好安全引导**：若禅道私有部署限制必须前往个人中心生成 API 密钥，提示卡片将明确展示已识别的账号与产品，并提供一键直达个人中心的跳转链接。

#### 4.2.2 常规分步配置流程
1. 填站点/API 版本与 Token → 测试身份/只读资源访问。
2. 成功后读取产品列表，按名称搜索选择产品。支持分页，不只读取第一批；列表无权限但已知产品 ID 时保留高级手填及单产品验证。
3. 配置默认提交目标：产品必选；项目、执行、模块、指派人、影响版本按该版本和产品能力加载。影响版本选项与提交值分开显示，不盲目将展示名称当 ID。
4. 上游产品/项目变更后清空或重新验证关联选项，不携带旧项目的执行或版本。
5. 保存配置；Bug 提交预览展示实际目标，允许单次覆盖，不改变全局默认。

只读产品检测必须解析该版本的成功/失败结构并检查真实产品标识及名称。不能把 HTTP 200、登录页或默认产品名称当成成功。能力状态分别显示产品读取已验证、创建未验证、附件未验证。

### 4.3 Bug 提交与附件状态

提交前展示站点、产品、项目/执行、指派人、版本、严重级别、优先级和附件清单。严重级别与优先级独立配置，允许保留当前默认映射但在预览中可修改。

为每次提交持久化 submissionId、localBugId、连接 ID/修订、站点/API 版本快照、目标字段、请求状态、externalId、externalUrl、附件逐项状态。不要在报告中存 Token。

状态流程：待确认 → 创建中 → 已创建 → 附件上传中 → 完成/附件部分失败。超时但服务器可能创建成功时标记“结果未知”，保留上下文让用户核查；没有服务端幂等支持就不能声称本地 ID 足以保证网络写入恰好一次。

已提交默认显示“打开禅道 Bug”，不把“重新提交”作为主要按钮。另建一条必须显式确认。若创建成功而附件失败，externalId 和附件状态立即落库，重开侧边栏仍显示“仅重试失败附件”。

附件重试绑定原站点与原 externalId，不使用当前默认站点。原连接被删除或凭据失效时要求重新关联/授权；绝不将相同数字 ID 的附件发到其他站点。

创建与上传都设置全程超时；只读请求可有限重试，创建 Bug 超时不自动重试。附件更新与服务端实际能力对齐，不能假定上传一次就一定绑定成功。

## 5. 技术落地与迁移

建议模块：

- `src/shared/integrations/config/`：类型、版本、地址规范化和草稿校验。
- `src/background/integrations/`：统一请求、超时、连接测试与提交任务；不将长请求生命周期绑定到设置组件。
- `src/ai/providers/`：本地规则、任务网关、明确协议的模型适配器；保留现有上层任务接口。
- `src/shared/integrations/zentao/`：版本适配、资源读取、Bug 创建、附件上传。
- 设置页分拆 AI 与禅道配置组件；BugEditPage 只负责预览/发起/显示结果。
- 新增配置仓储及提交记录仓储，IndexedDB 变更新增版本。

凭据使用 credentialRef 与普通配置分离；仅扩展可信上下文读取，不下发给被测页面，不进入业务证据包、诊断导出或同步存储。该限制针对集成密钥，不改变用户要求保留的抓包原文。

旧配置迁移：heuristic/disabled 原样保留；remote 明确映射为“企业任务网关”，不得自动改成模型直连；保留旧禅道地址、产品 ID、影响版本和会话 Token。迁移后验证状态设为未验证，不继承过期的绿色成功提示。

第一期只维护一组活动默认配置，数据模型保留连接 ID，避免后续多连接扩展时破坏附件绑定。

### 6.1 关键失败路径闭环验证矩阵 (复查重点)

1. **[P1 闭环] 标签页匹配防误选与跨站 Token 隔离**：
   - 彻底废除 `url.includes(host)`，严格校验 `URL.origin` 与部署路径前缀 `pathname.startsWith(presetPath)`；
   - 模拟包含 `?next=https://zentao.hbisscm.com` 或搜索引擎关键词时，坚决返回 `found: false`；
   - 引入 `isSameZentaoSite`：探测到不同站点且未提取到新 Token 时，强制清空原 Token，绝不向新站点发送旧站 Token。
2. **[P1 闭环] AI 网关“连接假成功”与能力强校验**：
   - 拦截 HTTP 200 但 Content-Type 为 `text/html` 的网关登录重定向页，明确返回 `PROTOCOL` 错误；
   - 拦截空对象 `{}` 与非 JSON 响应；
   - **强校验协议版本**：仅接受受支持的协议版本（v1），收到 `version: 999` 等不受支持版本一律拦截报错；
   - **强校验任务名类型**：`supportedTasks` 数组元素必须全为非空字符串，含有数字或非字符串（如 `[123]`）直接报错；
   - **严格能力交集**：区分“网关声明能力”与“插件支持能力”，仅保留两者交集；若交集为空明确报 `CAPABILITY` 错误；
   - 拦截网关返回的业务错误（`fail`、`failed`、`error`）。
3. **[P1 闭环] 禅道业务失败假成功拦截与 v1 适配器实现**：
   - 拦截 `status === 'fail'`、`status === 'failed'`、`result === 'fail'`、`error`、`errmsg`；
   - 未指定产品时，若接口返回空产品列表，强制返回 `FORBIDDEN`，绝不虚假显示“支持读取产品”；
   - 必须解析出真实的有效产品实体（包含 `id` 与 `name`）才判定连接成功；
   - **专门增加 ZentaoV1Adapter 适配器**：
     - 请求路径严格切换为官方 v1 规范：`POST /api.php/v1/products/{id}/bugs`（不再盲目向 `/api.php/v1/bugs` 提交）；
     - 请求 payload 自动去除多余的 `productID` 包装，按 v1 规范构造字段；
     - 响应解析适配官方 v1 的 Bug 实体，支持 `status: 'active'` 等有效 bug 业务状态，提取真实数字 ID，避免误判失败；
     - 捕获并拦截 v1 返回的业务错误（如 `{ error: "产品不存在" }`）。
4. **[P2 闭环] 慢请求竞态覆盖防护**：
   - 引入 `aiProbeIdRef`、`zentaoProbeIdRef`、`productProbeIdRef`、`buildProbeIdRef` 世代隔离机制；
   - 用户任何输入变动或连续触发测试，旧请求世代作废，晚返回的慢请求对比世代直接丢弃，杜绝回写旧结果或旧产品列表。
5. **[P2 闭环] API v1 全生命周期保持**：
   - `SettingsPage` 新增 `zentaoApiVersion`（`v1` / `v2`）状态并持久化至 `chrome.storage.local`；
   - `normalizeZentaoUrl` 与一键探测自动识别 `/api.php/v1` 并在 UI 显示 `API V1` 标识；
   - `ZentaoClient` 各方法（`testConnection`、`fetchProducts`、`fetchProductBuilds`、`createBug`、`uploadScreenshot`）全程遵守配置的版本路径。
